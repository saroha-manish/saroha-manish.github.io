Multi-Carrier Provider Fraud, Waste & Abuse (FWA) Risk-Ranking Model

Project Overview

Built an explainable machine learning model that ranks medical billing providers by fraud, waste and abuse risk in auto casualty claims. The model compares each provider's 5-year billing behavior with the behavior of providers already flagged by the Special Investigations Unit (SIU). For each provider, it gives investigators a prioritized worklist with three outputs:

  • A risk probability
  • A risk tier (High / Elevated / Low / No Risk)
  • The 10 strongest reasons behind the score

The model uses ~806M bill lines from many insurance carriers. This gives a view of each provider across payers that no single carrier can get from its own data.

Key Features

  • Cross-carrier view: Profiles 377K+ providers at the Tax ID (TIN) level across 90+ client accounts.
  • Explainable scores: SHAP reason codes show the feature value, the direction of its effect and its share of the score.
  • Action-ready tiers: Probabilities map to review tiers for simple triage and workload planning.
  • Production pipeline: Monthly rebuild, model registry with version aliases, run logging and 7 automated output checks.
  • Gated promotion: A new model replaces the current “champion” only if held-out PR-AUC stays within tolerance.

Technology & Tools

  • Data platform: Snowflake (SQL, Notebooks, Workspace, Model Registry)
  • Language: Python
  • ML algorithms: XGBoost (final), LightGBM, HistGradientBoosting, Random Forest, Logistic Regression
  • Explainability: SHAP
  • Methods: Stratified sampling, feature engineering, collinearity pruning, stratified 5-fold CV, randomized hyperparameter search

Problem Statement

Fraud reviews were mostly manual and reactive. Suspicious billing was often found only after large payments had gone out. Investigators had limited capacity and no objective way to decide which providers to review first. Sophisticated providers also bill across many carriers, so single-payer tools cannot see their full pattern.

Solution Approach

  1. Data design: Extracted and validated bill-line data in Snowflake. Chose the provider TIN as the row level because the NPI was missing for 33% of providers and the SIU opens cases by TIN.
  2. Label construction: Kept all 7,507 SIU-flagged providers. Drew a stratified “not-flagged” sample of 71,837 providers by customer, provider type and claim volume. Removed suspected offenders in two steps, including public OIG/state fraud lists.
  3. Feature engineering: Built 203 behavioral features in 15 groups, such as volume, pricing, procedure repetition, geography, attorney involvement and timing. Turned high-cardinality codes into share, diversity and concentration measures.
  4. Feature selection: Used missing-value, constant-value and collinearity rules, then tested 17 feature-set configurations. This cut the model to 104 features that investigators can check against the bill history.
  5. Modeling: Compared 5 algorithm families at the same capacity. Chose XGBoost and tuned it with a guard that rejected overfit configurations. Handled the 9.6:1 class imbalance with class weights instead of SMOTE, so the probabilities used for the tiers stay reliable.
  6. Deployment: Refit on all labelled data, registered the model in Snowflake, scored 298K unlabeled providers and wrote reason codes to a scores table.

Business Value

  • From reactive to proactive: Finds high-risk providers early enough to support pre-payment review.
  • Better use of investigators: Points SIU effort at a 59.6K-provider queue that holds 65.8% of total risk, which cuts time spent on low-yield reviews.
  • Finds cross-carrier schemes: Shows patterns that exist only when data from many payers is combined.
  • Defensible decisions: Every score comes with its reasons, so investigators have a clear, auditable place to start.
  • Keeps improving: Investigation outcomes feed back in as new labels to raise precision over time.

Challenges

  • Class imbalance (9.6:1): Used loss weighting instead of resampling, so risk-tier probabilities stay reliable.
  • Label noise: Some unflagged providers may be offenders. Reduced this with two-step exclusion of suspected providers.
  • Sampling bias: Stratified the sample and removed the sampling variable from the inputs. This makes the model learn behavior, not provider size.
  • Data quality: Fixed claimant and bill ID collisions across customers. Dropped NPI features with high missing rates. Began per-carrier checks so features measure provider behavior, not a carrier's workflow.
  • Overfitting: Added a train-validation gap limit (≤0.10) during tuning. This cut the gap by 22% with no loss in accuracy.
  • Explainability: Chose SHAP over split-gain importance to give accurate reason codes for each provider.

Positioning: Where the Model Fits in the Business

Business Context

The company reviews auto casualty medical bills for many insurance carriers, so its data shows how each provider bills across all of them. The model uses this pooled view to find risky providers that no single carrier can see alone.

Place in the Claims and SIU Workflow

Step What happens Model's role
1. Bill intake Providers send medical bills for auto injury claims Source of billing behavior
2. Bill review Bills are repriced, with review flags and endnotes Review results become model features
3. Data warehouse Bill lines from all carriers load into Snowflake Monthly feature rebuild at provider TIN level
4. Risk scoring Model scores every provider Gives probability, risk tier and 10 reason codes
5. SIU triage Investigators work the High and Elevated tiers first Sets the order of the worklist
6. Investigation Medical record review and corroboration Reason codes give the starting point
7. Action Pre-payment review, pended bills or referral Supports earlier action, before payment
8. Feedback Case results return as new labels Retraining makes the model more precise

Who Uses the Output

  • SIU investigators: Get a ranked worklist with the reasons behind each score.
  • SIU managers: Use risk tiers to plan capacity and assign cases.
  • Bill review and claims teams: Get risk signals for pre-payment review and pend decisions.
  • Carrier clients: Get cross-carrier insight that their own data cannot give.

Strategic Value

  • Turns the company's multi-carrier data into a competitive advantage that single carriers cannot copy.
  • Moves fraud detection from manual and reactive to data-driven and proactive.
  • Adds a scalable, explainable decision-support layer to the existing bill review platform.
Guardrails: The model is a triage tool, not a decision tool. A high score is a lead, not proof of fraud. Investigators make every final decision after human review of the records.
